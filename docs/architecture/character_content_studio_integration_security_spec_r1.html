Plugin / MCP / API Integration Policy

既存製品の機能を積極的に利用する。ただし「MCPがあるから接続する」のではなく、公式性、権限範囲、ローカル性、監査可能性、再現性を評価して接続方式を選ぶ。Productionの正本データと公開承認はCharacter Content Studio側に残す。

3. Eagle — Full Integration

採用：Eagleは「補助ツール」ではなく正式なReference Catalog Integrationとする。公式MCP Server + Web API v2を両方使い分ける。

Official MCP Server

自然言語/Agent操作、素材整理、タグ・分類、探索など対話的な作業に使用。

searchorganizetagarchive

Web API v2 / Plugin API

Studioの決定論的処理：asset snapshot、tag update、folder/smart-folder、comments等。

item CRUDfolderstagscomments

ルール

  • Eagle libraryのファイルを直接filesystemで改変しない。公式API/Plugin経由。
  • Generationに使う参照はStudio Asset Storeへsnapshotしsha256を保存。Eagle側移動に再現性を依存させない。
  • 「検索・タグ付け・コレクション整理」はEagle MCPへ積極的に任せる。
  • Studioが作品状態の正本、Eagleは素材カタログの正本。

Sources: Eagle Web API v2 / Plugin API / Eagle MCP Server.

4. ComfyUI — MCP + Deterministic Runtime

Comfy-Org comfy-mcpを活用

live installのnode/model/template introspection、workflow validation、開発時のworkflow実験、job monitoringに利用。

Productionは固定Workflow Adapter

採用画像を生成する本番経路はversioned WorkflowTemplate + slot入力。Agentに自由なgraph書換えをさせない。

UsePath
「今インストールされているmodel/nodeは？」MCP introspection

公式Comfy MCP自身も「sandboxではない」と明示する。専用Comfy workspaceを使い、partner API keyは必要時のみ、remote Comfyはprivate network + authを前提とする。

5. Blender — Restricted MCP Only

Blender MCPのコミュニティ実装は有用だが、任意Python実行を公開する実装もある。ProductionのStudioからそれをそのまま使わない。

Allowed

  • scene inspect
  • load pose preset
  • set camera
  • set transforms
  • render pose/depth
  • export under workspace

Blocked by default

  • arbitrary Python
  • shell command
  • unrestricted filesystem
  • network download
  • plugin install

Deployment

  • 127.0.0.1
  • workspace allowlist
  • telemetry off
  • named tools only
  • snapshot before destructive mutation

候補OSSはsecurity modelを持つ実装を監査後に採用可能。ただしversionをpinし、Studio側のPoseProvider interfaceの外へMCP固有仕様を漏らさない。

6. CLIP STUDIO PAINT EX — Plugin / Auto Action / Handoff

公式プラグイン機構は積極利用するが、公開SDKはフィルタープラグイン中心。一般的な文書Automation APIがある前提にはしない。

7. Publishing / Browser Automation

公開は「公式API/安全な統合があればそれを優先し、無ければPlaywright」。Playwrightを製品の汎用統合基盤にはしない。

  • 専用browser profileを使用し、通常ブラウザのCookieを直接参照しない。
  • 投稿前にEdition Preview + Approval。
  • publication idempotency keyを保存。
  • 不明な成功状態では自動retryしない。URL/screenshot/stepを保存して人が判断。
  • selector smoke testを別jobで実施。

各IntegrationのtoolをDomainから直接呼ばず、Application Portを通す。これによりMCP serverを交換してもProject/Scene/Asset schemaは変わらない。
