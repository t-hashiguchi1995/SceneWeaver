2. Wardrobe Market / Virtual Try-On

MARKET-01 — Wardrobe Market Search / Recommendation

No new model required
Purpose
衣装をマーケット型UIで発見し、Project/Character contextに合わせて絞る。
Technology
SQLite FTS5 + structured filters。category, region, style, season, color, source, verified, compatibilityをindex。推薦は最初はrule score。
Required prompt
なし。生成AIを使わず成立させる。自然言語検索が必要ならLLMGatewayで検索条件JSONへ変換するだけで、画像生成モデルは増やさない。
Score example
0.30 scene_style + 0.25 season + 0.20 character_compatibility + 0.15 color + 0.10 favorite/history
Output
MarketplaceItem IDs + score + reason。

GARMENT-01 — Garment Plate Generation / Import Normalization

gemini-2.5-flash-image
Purpose
Try-Onに使いやすい、白背景・人物なし・衣類単体のcanonical referenceを作る。
Technology
Google Image Provider。カテゴリ別aspect ratio。生成/写真importの2モード。
Canonical prompt — create
Japanese fashion apparel terminology encyclopedia illustration plate.
Isolated single garment, front view, centered on a pure white background.
No person, no face, no body, no mannequin, no hanger, no stand, no extra props.
No text, no watermark, no logo, no collage.
Clean colored fashion illustration, even studio lighting,
high detail of silhouette, fabric, seams, and trims.

Create a fashion encyclopedia plate of the garment described below.
Category: {category_en}. {category_hint}.
Item name: {name}.
Garment: {garment_description}.
Canonical prompt — import from photo
Redraw the clothing from the input image as a fashion encyclopedia plate.
Keep the garment's colors, silhouette, fabric, prints, seams, trims,
and distinctive details.
Remove any person, mannequin, background, clutter, duplicated items,
logos that are not part of the garment design, and unrelated props.
Output one isolated garment centered on pure white background.
No text, no watermark, no collage.
Category: {category_en}. {category_hint}.
Save
canonical image, source URI/hash, prompt version, model id, category, region, garment description, license note。

TRYON-02 — Look Recipe: Tops / Bottoms / Shoes

Qwen Image Edit 2509
Technique
一度に全アイテムを要求せず、regionごとに順次edit。各stepの採用Assetを次stepのimage1へ渡す。
Tops / outerwear edit
Change only the upper-body clothing of the anime character in image 1
to match the TOP garment shown in image 2.

Ignore any skirt, pants, shoes, or unrelated item visible in image 2.
Keep exactly the same face, hair, pose, lower-body clothing, shoes,

Fit the top naturally on the body; do not overlay a flat cutout.

Target top:
{garment_description}
Bottoms edit
Change only the lower-body clothing of the anime character in image 1
to match the BOTTOM garment shown in image 2.

Ignore any top, shirt, sleeves, or unrelated upper-body item in image 2.
Keep exactly the same face, hair, pose, upper-body clothing, shoes,
background, framing, and lighting.
Fit the bottoms naturally on the body.

Target bottoms:
{garment_description}
Shoes edit
Keep the exact same anime character, face, hair, pose, clothing,
camera framing, and background from image 1.
Change only the footwear to:
{shoes_description}.
Do not change any other garment or body feature.
Order
tops/outerwear → bottoms → shoes → optional accessory。Conflict ruleはMarketplaceItem.regionで判定。

3. Dialogue / Narration

Dialogue LLMはImage Model Registryとは別のLLMGateway。Promptは固定バージョン管理し、structured JSONを必須とする。

DLG-01 — Dialogue Director

director_v1
You are a dialogue director for a character-driven comic.

Do NOT write the final line yet.
Given the character persona, relationship state, scene objective,
previous beats, and current beat goal, decide the communicative action.

Return JSON only:
{
  "speaker_id": "...",
  "addressee_ids": ["..."],
  "speech_act": "...",
  "intent": "...",
  "subtext": "...",
  "emotion": {"name":"...", "intensity":0.0},
  "delivery": {"volume":"...", "pace":"...", "pause_before":false},
  "action_hint": "...",
  "information_to_convey": ["..."],
  "information_to_avoid_repeating": ["..."]
}

Constraints:
- Preserve continuity with previous beats.
- Prefer subtext over directly explaining emotion.
- Do not invent facts not present in context.

DLG-02 — Character Line Writer

writer_v1
You write spoken Japanese dialogue for {character_name}.

Use:
- Persona rules
- Relationship state
- Retrieved positive voice examples
- DialogueDirector plan

Generate {candidate_count} alternatives.
Each must express the same intent but vary in indirectness, rhythm, and warmth.

Hard constraints:
- first person: {first_person}
- addressee form: {second_person}
- max characters: {max_chars}
- max fragments: {max_fragments}
- avoid forbidden patterns: {forbidden_patterns}
- do not narrate visible actions
- do not add stage directions inside the spoken line

Return JSON array:
[{"text":"...", "tone":"...", "fragment_hint":["..."]}]

DLG-03 — Dialogue Critic

critic_v1
Score each dialogue candidate from 1.0 to 5.0 on:
character_fidelity, continuity, subtext, spoken_naturalness,
information_economy, repetition, bubble_fit, visual_redundancy.

Do not rewrite candidates.
Return JSON only with scores, short evidence, and blocking issues.

A blocking issue includes:
- contradiction with locked canon/state
- wrong first/second person
- invented factual event
- explicit explanation of subtext when indirectness is required
- text too long for the configured budget

DLG-04 — Narration Writer

narration_v1
Write Japanese narration for a comic panel/page.

Narrative function: {function}
Narrator profile: {narrator_profile}
Visible information summary: {visual_summary}
Story context: {context}

Rules:
- Do not merely restate what the image visibly shows.
- Add time, causality, memory, emotional implication, or narrative transition.
- Keep it concise: max {max_chars} Japanese characters.
- Maintain the narrator's POV and tense.
Return JSON: {"text":"...", "function":"...", "redundancy_risk":"low|medium|high"}

5. Review / CSP / Publication

Human final decision
Required model
なし。MVPはdeterministic checks + metadata + human review。新しいVision modelを必須依存にしない。
Checks
dimension/file integrity, expected candidate count, seed/workflow presence, state mismatch flags。identity/pose automated scoreはoptional extension。

No prompt/model

CSP role

6. Mandatory Prompt Engineering Rules

Semantic before textual prompt

  • DBの正本はIntent/Outfit/Pose/Camera等。
  • 最終promptはCompiler output。
  • Prompt変更でProjectデータをmigrationしない。

One edit, one responsibility

  • Try-Onで表情を同時変更しない。
  • Expression Editで衣装を変えない。
  • Tops/Bottoms/Shoesをregion別に処理。

Locked data is immutable

  • Lock済みセリフをVision/Image側が書き換えない。
  • 採用元Assetをin-place編集しない。
  • 新しい結果は派生revision。

Every generation is reproducible

  • Prompt version
  • compiled payload
  • model/workflow IDs
  • seed and refs hashes

9. Acceptance Criteria

  • Wardrobe MarketのItemを検索し、Detailから1クリックでTry-Onへ送れる。
  • Tops/Bottoms/ShoesをLook Recipeとして保存し、region別Qwen editで順次適用できる。
  • 各Generation結果から使用Prompt version / fixed model / workflow / seed / refsへ辿れる。
  • Story、Try-On、Shot、Expression、Publishの各機能にPrompt/技術仕様が存在し、コード内に独自promptを散在させない。
  • Production Image PathはAnima / Anima LLLite / Qwen Image Edit / Google Image Providerだけで完結する。
  • 旧アプリのExperiment/Trial/Pipeline schemaへの互換性を設計要件にしない。
