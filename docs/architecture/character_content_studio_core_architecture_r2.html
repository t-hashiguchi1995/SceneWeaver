1. 目的・非目標・設計原則

目的

  • 同一キャラクターの見た目、口調、関係性、衣装を継続管理しながら複数Scene/作品を制作する。
  • セリフ・ナレーション・演技を起点に、Pose/Camera/Outfit/画像生成へ接続する。
  • 固定された生成モデルをCapability経由で使い、生成条件を再現可能に保存する。
  • Virtual Try-On、Wardrobe Market、Eagle、ComfyUI、CLIP STUDIO、投稿先を一つの制作フローへ統合する。

非目標

  • CLIP STUDIO相当のページ・コマ・吹き出し編集ソフトを再実装しない。
  • 任意ComfyUI Workflowを自動理解する汎用ノードエディタを作らない。
  • 旧PlaywrightアプリのDB/クラス/API互換を維持しない。
  • 初期からマイクロサービス化しない。
  • 人間承認なしの完全自律公開を標準にしない。

設計原則

原則意味
Semantic Firstprompt文字列よりScene/Beat/Outfit/Pose等の意味データを正本にする。
Human in the Loopセリフ、採用画像、衣装採用、公開は人間がLock/Approvalできる。
Adapter BoundaryMCP tool名、Comfy node ID、Playwright selectorをDomainへ漏らさない。
Reproducibilitymodel/workflow/prompt/seed/ref/hashを保存。
IdempotencyJob再実行・Publish再試行で重複副作用を防ぐ。
Progressive ComplexityCSP/Blender/高度制御は必要な場合のみ。
Immutable Approval承認後のEdition/Script revisionは凍結し、変更時は新revision。
Observable Jobs長時間処理はDB-backed Jobとして進捗・失敗・再試行を追跡。

4. 継続状態 / State Resolver / Invalidation

Sceneは初期状態を持ち、Beatごとの差分を順に適用して「その時点の有効状態」を解決する。

Scene.initial_state
  + Beat01.state_delta
  + Beat02.state_delta
  ...
  = EffectiveState(at Beat N)

EffectiveStateの主項目

  • outfit / accessories / hairstyle
  • emotion baseline
  • relationship state
  • held objects / location substate
  • known callbacks / story facts

Invalidation Rules

変更Staleになるもの維持可能
Locked Script本文変更Visual Director提案、ShotSpec、未採用Generation、lettering hint過去Asset自体
Outfit変更ShotのOutfit関連RenderPlan、生成候補ScriptEvent
Pose/Camera変更RenderPlan、生成候補Locked Script、Outfit State
Prompt template version変更既存ResultはstaleにしないProvenanceで旧version保持
Release Edition本文変更ApprovalMaster asset

8. Job Orchestration / State Machines

Job Worker Rules

  • jobs tableを正本にし、workerがqueuedをclaim。
  • heartbeat_at更新。stale running jobはrecovery対象。
  • max_attempts, retry_policy, external_job_ref, progress_json。
  • UIはSSEでeventを受信し、切断後もDB状態から復元。
  • Publishはapproval_at必須。

State Machines

Project:
draft → story → visual_production → csp_finishing → release_ready → published → archived

ScriptEvent:
draft → candidate → selected → locked → superseded

GenerationJob:
queued → running → succeeded | failed | cancelled | blocked

Asset:
generated → shortlisted → adopted | rejected → handed_off → released

ReleaseEdition:
draft → validating → ready → approval_required → approved → publishing → published | failed

PublicationJob:
queued → publishing → published | ambiguous | failed
ambiguous: 外部サイト投稿が成功したか判定不能な場合。自動retryせず人間確認。

11. Error / Recovery

FailureBehavior
ComfyUI offlineJobをblocked/queued保持。UIでhealth表示。データ消失なし。
Workflow validation error実行前にslot/node mismatchを検出しsubmitしない。
VRAM/OOM失敗理由保存。retry actionで低解像度/別workflowを提示。
Eagle offlineStudio内部Assetで継続。sync pending。
Blender integration failureCSP 3D / OpenPose手動経路へfallback。
CSP export未検出handoffは保持し、watcher再開可能。
Playwright selector破損Publication failed、step/URL/screenshot保存。
Publish ambiguous自動retry禁止。人間確認。
App/Worker restartDB Job stateから復帰。stale runningをrequeue候補に。

14. Acceptance Criteria

  • 同一Characterで5 Beat以上を作り、状態継続とOutfit変更履歴を追跡できる。
  • Lock済みScriptは画像生成/再生成で変更されない。
  • Market → Try-On → Wardrobe採用 → Scene適用が成立。
  • 固定WorkflowをTemplate差替えだけで切り替えられApplication修正不要。
  • 採用画像からShotSpec、prompt version、seed、workflow snapshot、参照Assetへ遡れる。
  • Eagle停止中でも既存Projectを閲覧/編集できる。
  • worker/application再起動後にJob状態を復旧できる。
  • CSP HandoffとBatch Export Round-tripが成立。
  • X/pixiv/Patreon Editionを独立Previewし、Approval後にPublishできる。
  • Integrationはtrust/scope/auditを持ち、Productionで任意code executionを要求しない。

15. Pydantic Contract Examples

from pydantic import BaseModel, Field
from typing import Literal

class EmotionSpec(BaseModel):
    name: str
    intensity: float = Field(ge=0.0, le=1.0)

class BeatSpec(BaseModel):
    speaker_id: str | None = None
    intent: str
    subtext: str = ""
    emotion: EmotionSpec
    action: str = ""
    state_delta: dict = {}

class ScriptEventSpec(BaseModel):
    kind: Literal["speech","inner_voice","narration","caption","offpanel_voice","sfx"]
    speaker_id: str | None = None
    text: str = ""
    locked: bool = False

class CameraSpec(BaseModel):
    shot: Literal["closeup","bust","medium","fullbody","wide"]
    angle: str = "eye_level"

class SemanticRenderSpec(BaseModel):
    character_id: str
    outfit_state_id: str | None = None
    emotion: EmotionSpec
    pose_id: str | None = None
    gaze: str | None = None
    scene_id: str
    camera: CameraSpec
    style_profile_id: str
