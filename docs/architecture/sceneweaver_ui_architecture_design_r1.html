1. 目的と設計原則

SceneWeaverのDomain・Persistence・Generation provenanceは既に強い。次の重点は、制作物を「見て、比較して、編集して、採用して、次工程へ渡す」ためのUIを完成させることに置く。

Semantic First

Character / Outfit / Scene / Shot を正本とし、Promptは生成時の可視・編集可能なDraft。Prompt文字列だけをアプリの正本にしない。

Human-in-the-loop

AI候補を直接確定せず、比較・手修正・採用・ロックを明示操作にする。過去GenerationAttemptは不変。

Reproducibility

最終Prompt、Seed、Model、Workflow、Control、Profile、Component参照をGenerationAttemptに保存し、再現と比較を可能にする。

設計上の中心: 「何を生成したいか」→「どのPromptを送るか」→「何が生成されたか」→「どれを採用したか」を、画面とデータモデルの双方で追跡可能にする。

16. Backend / API 改修

16.1 Asset content API

GET /api/v1/assets/{asset_id}/content

200 image/png | image/jpeg | ...
Cache-Control: private, max-age=...
ETag: sha256
Content-Disposition: inline

FilesystemAssetStoreの path_for_uri() を利用し、asset:// をブラウザへ直接出さない。Asset ID経由で認可・存在確認を行う。

16.2 Attempt replay API

POST /api/v1/generations/{attempt_id}/replay
{
  "seed_mode": "new" | "same",
  "copy_prompt_to_draft": false
}

Frontendがuse_pose等を推測しない。Application層でAttempt snapshotからRenderPlanを再構築する。

16.3 Prompt autosave

既存PUTを利用可能。更新競合を避けるなら updated_at / revision をrequestに持たせ、optimistic concurrencyを追加。

16.4 Settings適用

ContainerのImageBackendキャッシュを (backend, comfy_url, config_revision) に対して再生成する。Settings更新後も古いBackendを保持しない。

18. セキュリティ / Legacy Importer

ZIP安全展開

member pathを正規化し、..・絶対パス・drive letterを拒否。
symlink / special fileを拒否。
展開ファイル数上限を設定（例 5000）。
1ファイル上限、総展開サイズ上限を設定。
対象拡張子をyaml/yml等へ限定。
temporary directoryをrun単位で作成し、finally cleanup。

Import境界

Legacy YAMLは一方向Importのみ。runtimeで直接参照しない。成人向けは明示マーカーのみで判定し、曖昧なものはunsupported。

21. 受入条件

Projectを開くだけで現在のScene/Shot/Generation/CSP状況が把握できる。
Character Persona / VisualIdentityをUIから編集・再読込できる。
Prompt編集はAutosaveされ、画面遷移して戻っても保持される。
Generation Reviewで4候補すべての実画像を表示できる。
Adopt/RejectはDBへ保存され、CSPはAdopt済みAssetだけを受け取る。
「同条件で再生成」と「完全再現」でseed挙動が仕様通り。
CSP HandoffがSettingsで指定した出力先へ作られる。
Comfy設定変更後、再起動なしで新Backend設定が反映される。
Legacy zip importはpath traversal / symlink / oversized archiveを拒否する。
Mobile/Tabletでも主要画面が操作可能で、Top navigationが溢れない。
