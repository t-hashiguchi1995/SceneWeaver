1. 機能の完成判定原則

新しい定義: 5段階すべてを通って初めて「機能実現済み」とする。

5. Continuation採用、保存、履歴、再生成、次工程へ進めるAdopt → Visual Library → CSP

3.1 画面上の切替

Shot Studio上部に「生成エンジン」を置く。選択したCapabilityは即Shotへ保存し、Generate直前の取り違えを防ぐ。今回のUI変更で BaseRender ↔ LayoutGuidedRender の選択導線を追加する。

3.2 比較モード

モデル比較は2種類を明示的に分ける。比較結果には comparison_mode と共有条件を保存する。

モード条件用途
Strict PromptPositive / Negative / Seed / Resolutionを可能な範囲で同一化。Prompt enhancer等はOFFモデルそのものの挙動差、workflow回帰テスト
Production Fair共通Semantic Specから各モデル向けcompilerで最適化。元Semantic hashを共通化「実際に使うならどちらが良いか」の比較
Shared Semantic Spec→Anima Compiler→Anima Result
Shared Semantic Spec→MOSS Compiler→MOSS Result

比較Reviewでは左右または列表示で、モデル名、seed、compiled prompt、workflow hashを同時に確認できるようにする。

4. UC-IMG — 直接画像生成

UC-IMG-01: Promptから画像生成

画像生成→Engine選択→Prompt入力→Generate→Preview→Adopt / Save

Quick Testを最終的に Image Lab へ置換する。Project / Story / Beatを作らなくても、最短で実画像を生成できる入口にする。

受け入れ条件

  • UIからPrompt、Negative、Engine、Resolution、Seedを設定できる。
  • Anima / MOSSを切り替えられる。
  • Real Comfyでdecode可能な画像を生成する。
  • 結果をUIで拡大表示し、Visual Libraryへ保存できる。
  • 同条件再生成と別モデル比較へ進める。

5. UC-VTO — Virtual Try-On

UC-VTO-01: 任意画像2枚から試着

人物画像Upload+衣装画像Upload→Try-On→4候補→Adopt

現状は登録済CharacterとMarketplace Itemに依存している。共通Asset Picker導入後、人物/衣装の両方に「Upload / Library / Character / Wardrobe」タブを提供する。

UC-VTO-02: Character × Wardrobe

Character Aに Outfit A/B/C を順番に試着し、A→B→C→Aで過去の衣装情報が混入しないことを必須検証とする。

6. UC-POSE — ポーズ指定

Shot / Character→Pose: Upload / Library→Strength→Generate→結果比較

asset://... URI手入力をユーザー導線から排除する。将来はOpenPose Editor等も選択肢に追加できるが、まず画像UploadとVisual Library選択を完成させる。

7. UC-CHAR / UC-WARDROBE

Character

名前→顔/全身Upload→Visual Identity→Persona→Save

identity_ref_asset_ids や tryon_base_asset_id をID手入力させず、Asset Pickerで設定する。

Wardrobe

衣装Upload→名称/説明/タグ→保存→Try-On

OutfitProfileのcharacter ownershipを必須検証し、別Characterの衣装をsilentに利用しない。

8. UC-LIB — Visual Library

検索・自動タグだけでなく、制作素材を入れる入口とする。

  • 画像を追加
  • 種類: Character / Outfit / Pose / Background / Reference
  • PixAI auto-tag
  • User tagはauto-tagと分離
  • 生成物、import素材、採用素材を由来付きで表示
  • Character / Try-On / Pose / Multi-ref のAsset Pickerから再利用

10. UC-ADULT — R-18 pipeline

R-18はオプション検証ではなく必須。成人として定義したテストCharacterのみを使用し、Projectの content_rating=adult を明示的な入口にする。

Fixture目的

11. 共通 Asset Upload / Picker

最優先の共通UI基盤。 Character / Try-On / Pose / Visual Library / Multi-refで重複する入力問題を一度に解決する。
AssetPicker ├─ Upload ├─ Visual Library ├─ Recent ├─ Character refs └─ Wardrobe 選択結果 ├─ asset_id ├─ thumbnail ├─ kind / role └─ provenance

13.2 R-18 / adult pipeline に関する制約

重要: R-18 / adult pipeline の検証は、成人であることを明示した安全なfixtureのみに限定する。上記の標準キャラクターセットのうち、成人向け検証に使うのは原則として T11 実写系の女性（成人コスプレイヤー）、または将来追加する成人であることが明確なオリジナルfixtureとする。
  • T01〜T10 は主に一般生成、モデル比較、衣装切替、ポーズ、同一性維持、Review UX の検証に用いる。
  • adult profile / AdultRender / R1〜R3 の検証では、未成年または年齢が曖昧に見えるキャラクターは使用しない。
  • R-18検証用manifestには、fixtureが成人向け利用可能であることを記録する。

13.1 merge gate

#B / #Cでは test:e2e:live:required 相当を用意し、Comfy unreachableもFAILとなる必須実行モードを採用する。通常開発用のskip可能live suiteとは分離する。

13.2 実画像の最低検査

  • PNG/JPEG/WebPとしてdecode可能
  • width / height ≥ 512（テスト条件に応じて固定）
  • byte_size > 0、SHA256あり
  • model_id / capability / workflow / seed / prompt hash / external job ref保存
  • Playwright artifactとして生成画像・manifestを保持
